# 體育賽程與轉播來源

## 入口

- `/sports`：NBA／MLB 同頁觀賽中心，整合賽程篩選、直播播放器與來源切換，不需登入後台；不變更前台選單。
- `/sports?watch={event-id}`：直接選取比賽並查詢轉播，網址可分享；不指定比賽時不抓取任何播放來源。
- `/sports?league=MLB`、`/sports?league=NBA`：聯盟捷徑。
- `/sports/events/{id}`：保留原賽事詳情與獨立播放器入口，提供「同頁觀看」捷徑；帶 `Accept: application/json` 時供觀賽中心查詢同場來源與已驗證的播放入口。
- 品牌為 **Easonn SPORTS**，不提供返回部落格連結。
- `/sports/player/{token}`：獨立站內播放器，支援網頁全螢幕、Esc 還原、原生螢幕全螢幕、重新載入及停止播放；HLS 來源的播放／暫停／音量使用 video 控制列，iframe 來源由原站控制。
- 支援運動分類、台灣日期、開賽時間篩選及中英文隊名搜尋；不需資料表、migration、API 金鑰或前端編譯。
- 預設 `/sports`（或 `?range=current`）僅顯示台灣時間今天起的賽程，保留今天已開賽的比賽；日期及同日時間由早到晚排列。
- `?range=history` 顯示今天以前、上游仍提供的歷史賽事，日期由近到遠，同日時間由早到晚；並非完整歷史資料庫。
- 指定 `date=YYYY-MM-DD` 時優先查該台灣日期，可直接選擇過去日期；其他分類、聯盟、搜尋及開賽時間條件仍生效。切換賽程範圍會清除指定日期，保留其他條件；「清除」回到預設今天起。
- 頂部總數、聯盟及運動分類場數隨日期範圍／指定日期計算；範圍切換按鈕的場數表示來源中各範圍的總數。非今年的日期標題包含年份，當天標示「今天」。台灣午夜邊界每次請求重新計算，不受上游快取影響。

## 影片傳送限制（使用者明確要求，2026-10-13）

- 影片與音訊分段必須由觀眾瀏覽器直接向來源 CDN 下載；不實作任何額外的伺服器影片轉送，包括本站後端、第三方代理、Worker／邊緣代理，也不作為故障 fallback。
- 後端僅解析來源資訊、處理有大小限制的小型播放清單，以及既有的 HEAD 轉址資訊。不得因 CORS、Origin 限制或來源故障而改成影片代理。
- 無法直送的來源保留原站連結，不標示為可用的自製播放器來源。新來源須以未被原站預先載入的新片段驗證完整播放與網址刷新後，才可啟用。
- 保留原始畫質與既有直播同步設定；不以自動降畫質或刻意增加直播延遲處理卡頓。

### Streameast 自製播放器動態解析（2026-10-13）

- `StreameastService` 完成原有雙方球隊與開賽時間核對後，才附上 resolver、賽事 ID 和開賽後 6 小時的期限。`StreameastHlsService` 只接受已觀察的 `gooz.aapmains.net/new-stream-embed/{數字頻道}`，以及無 query、`ad=111` 或 `3newa=22` 的形式；其他來源仍保留原連結。來源列表／播放器註冊不提前解析 HLS。
- 點選播放才讀取來源頁的 literal `const source`／`source` 或 `source: window.atob(...)` 值；只作字串和 base64 解析，不執行原站 JavaScript。所有候選必須指向同一個允許的 URL，且清單頻道必須和 embed 頻道一致。
- 當前入口 `chatgpt.hereisman.net/playlist/{頻道}/load-playlist` 在未附標頭時回應 403；附固定的 gooz Origin／Referer 後回應 HLS。入口與媒體清單均附這些固定標頭，不使用使用者 Cookie。媒體清單在無標頭時曾間歇回應 403；8 組對照中無標頭 3 次 403、附標頭 8 次均 200，故不能只憑一次無標頭成功就省略。入口目前只接受已觀察的單一 rendition master；直接宣告已驗證媒體清單的舊格式也可解析。新多音軌、多 rendition 或未知格式須另行確認，不默默猜測來源。
- 已觀察的清單主機：`pl.playlist3.space`、`pl.playlist5.space`、`pl.kamfir5.space`、`pl.whywelove2.space`、`pl.wearestrong1.space`；影片主機：`a.newstore1.space`、`a.newstore4.space`、`a.newstore5.space`。設定列於 `config/streameast.php`，不以萬用網域放行。清單限制為相同頻道的 `/playlist/{id}/{已知媒體主機}/caxi`；影片限制為同頻道 base64 路徑下的已觀察 TS 檔名（`.txt`／`.ts`）。未知主機、跨頻道、重新導向、編碼路徑、額外 query、使用者資訊、埠均拒絕。
- 解析結果共用快取 45 秒、有鎖和 15 秒失敗退避。入口短暫失敗時可使用最近 180 秒內仍在白名單的已驗證 CDN 網址，失敗不延長期限；仍即時抓取該 CDN 的最新媒體清單，不重播舊片段或增加直播同步距離。超過期限即停止沿用。來源頁／清單最多 256 KiB，連線 3 秒、總共 8 秒。播放器持續載入同一個本站播放清單入口，後端在刷新後解析當前 CDN，不再把單場網址寫死，也不把舊 CDN 留在長效子清單票證內。
- 後端只取得來源頁和小型播放清單，影片仍由瀏覽器直連 CDN，沒有影音代理、第三方播放器腳本或廣告 iframe。來源提供的解析度原樣交給 HLS；這場 Streameast 的 master 宣告單一 1280×720，並非把 GKS 1080p 轉碼降畫質。
- 回歸測試涵蓋賽事綁定／期限、註冊不連線、兩種 literal 格式、CDN 更新後原播放入口仍有效、跨頻道／未知主機／不支援格式拒絕、錯誤退避、大小限制、影片不經後端。Chrome 已實際播放當前 57983，解碼 1280×720，清單經 localhost、影片由 newstore5 直送。最終標頭／主機修正後的 126.7 秒觀察中，約 5.8 秒開始播放，至約 120.8 秒才發生後續等待；之後上游入口與媒體清單回傳 404。同場 57989 入口亦回傳 404，重新取得來源列表已無 Streameast。因此已驗證接入可播及跨快取更新，但無法完成更長時間或整場穩定性驗證，不能宣稱原站停流已修復。89 項相關後端測試（857 assertions）與 Pint 通過。

## 站內播放器：清單經後端、影音由 CDN 直送

2026-10-13 初期以單場固定映射接通 Streameast 頻道 57972；該映射於台灣時間 10:00 到期，而且不涵蓋當前光芒對守護者的 57983／57989 頻道，造成介面只顯示原站觀看。現已移除這筆過期映射，改用上述賽事綁定的動態解析；`config/sports_player.php` 的精確映射功能仍保留供其他已驗證整合使用。

- `SportsPlayerService` 登記／顯示頁面不連線上游。播放連結有效 6 小時，每次請求重新確認來源映射、期限及主機。
- 進入播放器頁面後自動載入本地固定版本 `public/vendor/hls/hls-1.7.3.min.js`（官方 hls.js 1.7.3，Apache-2.0 授權檔附於相同目錄），由 ArtPlayer 5.4.0 提供控制介面、HTML video 解碼播放。ArtPlayer 與繁體中文語系同樣由本站提供、僅播放器頁面載入，來源 npm tarball 已驗證 SHA-512，附 MIT 授權。具備 MSE 的瀏覽器使用 HLS.js；沒有 MSE 而支援原生 HLS 的瀏覽器由系統播放，畫質改為系統自動，移除無法控制的播放模式選單。
- Laravel 只代理 `/sports/player/{token}/hls/playlist` 與持有加密票證的子播放清單。**影片片段、初始化片段、金鑰均保留來源 CDN 絕對 URL，不透過本站轉送；無影音代理 fallback。**來源 CDN 必須允許瀏覽器讀取。
- 清單 fetch 使用 PHP cURL；一般來源不附原站 Origin／Referer，GKS 則使用 HTTP/2 及固定的 embed.st Origin／Referer。均不使用使用者 Cookie、不跟隨重新導向；只允許設定中的 HTTPS 主機／路徑，限制 256 KiB、連線 3 秒、總共 10 秒。非 HLS 回應、非白名單 URI 及上游失敗均關閉該次請求，以 503 和 Retry-After 回應。
- 子清單票證綁定播放器、URL、類型及期限。請求不得指定任意來源，也不能將票證用來轉送片段／金鑰。舊 `/sports/media` 和 `/sports/player/{token}/source` 均保持 404。
- 清單使用獨立 file cache，每來源固定 8 個槽，成功快取 1 秒、失敗退避 2 秒，加鎖避免同時重複取得。輪詢路由不啟動 session 或寫入 Cookie；保留頻率限制。
- 一般來源的自動畫質依播放器大小／網路狀況選取，通常上限 1080p；多畫質時可手選。省流量模式自動限制至可用的 720p 以下。單一畫質來源明示省流量模式不會降低其流量；GKS 使用固定畫質及重新連線切換，詳見下節。
- 均衡／低延遲模式分別以約 3／2 個片段距離作為同步目標。這個來源的片段為 6 秒；顯示的秒數是距 HLS 直播端點，**不是攝影現場到螢幕的延遲**。實際距離會受網路與上游影響，不承諾秒級或次秒播放。
- Worker 解封裝，目標前向緩衝 12 秒、最大緩衝設定 24 秒、保留已看 6 秒、容量目標 24 MiB；這些是 HLS 緩衝設定，不是整個分頁 RAM 上限。畫面資訊最多每秒更新一次。
- ArtPlayer 的手動暫停會停止 HLS 下載並保留有限緩衝，恢復播放重新取得直播；切換頁籤不再自動暫停。停止／離開頁面銷毀播放器、取消計時器並清除影片來源。瀏覽器或作業系統仍可能休眠背景頁面。致命錯誤僅作有限次恢復，失敗後顯示重試／切換來源。
- 保留 sandbox iframe 的相容路徑，但只有 `verified_embed_urls` 中實際驗證過的完整 URL 才可使用。目前 GKStreams 與 StreamEast embed 均未通過現有 sandbox，名單為空；不解除 sandbox 來假報成功。
- 自製 HLS 頁面不載入原站廣告腳本／廣告 iframe，能避開原頁彈窗和頁面廣告；**無法去除已混在影音裡的轉播廣告**。

### 驗證與已知限制

- 初期全後端轉送的臨時原型曾成功播放 177.97 秒、720p，但會產生大量伺服器出站流量；已捨棄該架構並移除 public 臨時端點。
- 隨後清單代理、片段 CDN 直送的原型通過播放驗證。正式頁面於本次修復後亦解碼 1280×720、播放時間持續前進超過 70 秒；Chrome 網路紀錄確認 CDN 片段 200，清單由本站提供。短暫上游失敗有恢復，但這不是整場穩定性保證。
- 修復前頁面已切換至 video，但 JavaScript 尚操作不存在的 iframe，造成 `Cannot read properties of null (reading 'addEventListener')`。現已依 video／iframe 分支初始化，並更新靜態資產版本。
- 以抽查每 6 秒約 3.9 MB 的片段推算，每人每小時約 2.34 GB 觀看流量；只有清單經本站時，本站每人每小時估約 1–5 MB，另加首次載入資產，非 AWS 帳單實測。

### ArtPlayer 介面（2026-10-13）

- HLS 頁面預設開啟聲音、音量 70%，進入後嘗試有聲播放。瀏覽器拒絕自動播放時停止下載，顯示「播放直播（含聲音）」按鈕，等使用者點擊後繼續，不再自動改成靜音。HLS 頁面使用 `sports-live-player.js`，iframe 頁面保留 `sports-player.js`，不混用兩種初始化流程；外部 iframe 的音量仍由原站控制。
- 播放器內整合播放／暫停、音量、畫質、均衡／低延遲／省流量、畫面比例、回到直播、子母畫面、劇院模式與全螢幕。只顯示來源實際提供的畫質；有多音軌時才增加音軌選單。
- 使用直播模式，隱藏不適合直播的總長度與一般影片進度列；不提供沒有來源支援的字幕、倍速或下載按鈕。

- 不啟用廣告／分析插件、截圖、背景迷你播放器、逐幀 UI 輪詢；沿用原有 HLS 小緩衝、Worker、CDN 片段直送與清單快取。
- 不提供影音代理 fallback；介面功能不會增加 AWS 片段流量。

### GKStreams／Sportsurge 動態接入（2026-10-13）

GKStreams 與 Sportsurge 在此賽事使用相同 Streamed 來源。公開 [Streams API](https://streamed.pk/docs/streams) 回傳 `embedUrl`，不是固定可轉用的 HLS URL。

- `config/gks.php` 啟用 `embed.st/embed/admin/{id}/1` 與 `embed.st/embed/hotel/{id}/1`，對應已測的 Fox HD 與 Main HD。ADMIN 2 的 `/m/` 回傳影片本體且本站 Chrome 直連失敗；GOLF 兩個頻道均回傳清單 404，這些來源保留原連結，不啟用影片代理。
- `GksService` 以來源 ID、provider 和頻道號建立二進位 POST `/fetch`，用回應的短效金鑰驗證、解析播放網址。使用現有 PHP cURL 與 OpenSSL，不需要瀏覽器常駐、Node／Python sidecar、第三方 WASM 或手動抄錄短效網址。註冊及顯示 HTML 不觸發上游請求。
- 本機隔離測試確認同一清單經 HTTP/1.1 回應 403，經 HTTP/2 及固定原站標頭回應 200。`GksTransport` 強制 HTTP/2 TLS，只處理固定握手端點及已知清單格式；握手最多 16 KiB，清單沿用大小／時間上限，禁止重新導向。
- 動態播放網址共用快取 45 秒、加鎖避免重複取得，失敗退避 15 秒。賽事開賽超過 6 小時停止提供。子清單票證綁定頻道畫質相對路徑，每次使用最新的已驗證來源網址，刷新後不會繼續引用舊的 secure token。
- 影片分段僅允許已驗證的兩個 TikTok CDN 主機，由瀏覽器直接取得；`gks-media.js` 驗證 RIFF／WebP 邊界及 TS 同步位元，支援 EXIF 內影音（ADMIN）及完整 WebP 後附加 TS（HOTEL），再交給 HLS.js。後端沒有下載或解包分段的路徑，不載入原站廣告腳本。
- HOTEL 的清單使用 `/m/{token}.ts` 轉址。後端只發 HEAD、禁止跟隨轉址及接收 body，僅接受 302 到上述 CDN；每清單最多 8 個、同主機最多 3 個並行請求，5 秒逾時。結果共用快取 90 秒、每來源固定 64 槽；單一轉址逾時保留其他已成功的結果。可暫用最近 12 秒內的清單，失敗不延長其期限，逾期仍回傳錯誤，避免無限使用過期資料。
- 此格式需要 HLS.js／MSE；僅支援原生 HLS 的裝置會顯示切換來源提示。為避免原型中的跨畫質時間軸錯誤，預設固定 1080p；手動切換畫質或模式會重新連線。低畫質清單存在不代表能直送播放；保留手動畫質並限制可選層級上下界，來源失敗時不自動改用其他畫質。意外的畫質切換會明示失敗，避免跨時間軸播放及錯標。Main HD 只有單一 1080p 時仍明示無法降低畫質。
- 本機站內頁面已解碼 1920×1080，連續播放近 5 分鐘，跨越多次來源快取刷新；刷新前後的網址雜湊與主機均已改變。Chrome 確認清單經 localhost、影片 CDN 200。此為本機驗證，尚未驗證 AWS 正式環境或整場穩定性。


### GOLF／INGEST 接入研究（2026-10-13）

- 直接以 GOLF provider 呼叫 `/fetch` 會取得 `/golf/stream/{id}/{no}/playlist.m3u8`，2194（尼克／灰狼）、2195（爵士／馬刺）的 1、2 頻道本次均回傳 404。這不能代表 GOLF 原頁實際使用的影片；先前只以這個結果判斷來源不可播，證據不足。
- Chrome 實際觀察 2194/1 原頁嵌入 `rockylive.st/source/streamed1.php?hd=519&id=2194&no=1`，Rockylive 以 literal `playerFrame.src = atob(...)` 指向 `embed.st/embed/ingest/streamednewyorkknicks/1`。2195/1 則使用 hd=528、id=2195，再轉到 `ingest/streamedutahjazz/1`。所有網址均來自實際頁面，不以球隊名稱猜 slug 或改寫 provider。
- 原頁回應並不固定：2194/1 重新載入曾改成直接使用 GOLF HLS 的 Clappr 頁面；2194/2 本次亦直接使用 GOLF HLS。解析器需按實際回應分支，不能把整個 GOLF 類型硬套成單一 iframe 或清單格式。
- 尼克 INGEST 在原站播放器也顯示 `hls:networkError_manifestLoadError`，Chrome 實際清單請求回傳 500／503。爵士 INGEST 則成功播放 1280×720（最終觀察播放時間 187 秒，畫面為 GAME HAS ENDED 賽後提示，並非仍有比賽畫面）；握手解碼可沿用目前 GKS 協定，真實清單位於 `/secure/{短效值}/ingest/stream/streamedutahjazz/1/playlist.m3u8`，本次 target duration=5、每片約 4.004 秒，片段為同 lb*.strmd.st 主機的 `/m/{token}.ts`。
- **更正直送可行性判斷**：先前 localhost 的 Chrome 對原站已播放過的同一片段做 Range 376 bytes 測試得到 206，但未排除瀏覽器快取，不能證明新的片段能從本站下載。接入完整播放器後，尚未由原站載入的新片段持續遭遇 CORS／403，沒有成功開始播放。以同一新片段作 HEAD 對照，Origin 為 localhost、null 或省略時均 403；Origin 為 `https://embed.st` 時 200、`video/mp2t`、`Access-Control-Allow-Origin: *`，有無 Referer 不改變此結果。該回應為影片本體，沒有可供直送的 302 目的地。標準 HLS 格式不等於允許跨站下載。
- 已加入 `GolfHlsService` 的按需解析：讀取 GOLF HTML（最多 1 MiB），只接受同頻道的已知 Rockylive iframe，再讀取 literal base64 INGEST 連結（最多 64 KiB）；也辨識已觀察的直接 GOLF 播放器分支。不執行原站 JavaScript、不猜隊名 slug。限制固定主機、路徑、參數及目標頻道；轉接映射快取 120 秒、短效清單網址 45 秒、失敗退避 15 秒，綁定賽事期限。
- **`gks.golf_enabled` 目前為 false**，不將 GOLF 列成可用的自製播放器來源；原站連結保留。解析器與相關測試已完成，但完整播放尚未通過。現有實作仍只代理小型清單，沒有增加影片代理、轉碼、緩衝或調低畫質。使用者已明確排除任何伺服器影片轉送方案；只有取得允許本站瀏覽器直接下載的來源，並通過完整播放驗證後，才重新考慮啟用。刷新清單本身無法解除 Origin 限制。

### GKS 智慧下載（2026-10-13）

- 本機 Chrome 曾重現 ADMIN 1080p 分段收到部分資料後停滯超過 20 秒、緩衝耗盡。`gks-media.js` 現以 Fetch 串流讀取監測實際收到的位元組，使用 HLS 1.7.3 的 fragment loader／stats 合約。清單仍用原來的 HLS loader。
- 連續 1.5 秒沒有下載進展，或整段下載已達片段時長（觸發門檻限制於 2.5–4 秒），才向**相同簽名 URL**補發一次 GET。原請求繼續下載，先完成且通過解封裝檢查的一份勝出，立即取消另一份；不拼接不同請求的資料，不將未解包的進度資料送入解碼器。
- 補發使用 Fetch `cache: no-store`，避免被瀏覽器併入相同的快取請求；不改 URL、主機或簽名，不增加 CORS 請求標頭，不保證建立不同 TCP 連線。HTTP 403／404 等不可重試回應不觸發補發。
- 每個 loader 最多兩個請求，共用 12 秒總期限，各請求首回應最多 5 秒；每個播放器最多每 5 秒補發一次，最近 32 個已補發 URL 不再補發（包括 HLS 重試）。同一主機連續兩次補發仍失敗後，30 秒內停用該主機的額外請求，原下載與 HLS 有限重試仍繼續；任何成功下載都解除該主機退避。每份回應最多 16 MiB。保留 HLS 的有限錯誤重試，沒有常駐背景預抓或其他頻道影片下載。卡住時可能增加部分重複流量，正常完成的片段只抓一次。
- 保持預設 1080p；啟用 `preserveManualLevelOnError` 並限制自動層級上下界。均衡／低延遲同步距離維持 3／2 個片段、前向緩衝 12 秒、最大設定 24 秒、容量目標 24 MiB；GKS 不因 stall 增加同步目標，維持 1 倍速，避免倍速追趕造成額外掉幀。不自動換來源或降畫質。這不表示網路中斷時實際直播距離不會變動。
- 暫停、停止、換來源、離頁均會中止原下載和補發、清除計時器，忽略晚到的舊回應。成功交付前一直保留同一個 stats 物件，另在 `stats.gks` 提供請求數、是否補發、勝出請求及接收位元組，供開發診斷；沒有遙測上傳。
- 後端仍只處理播放清單；不增加影音代理、不交換 CDN 簽名網址的主機、不改來源白名單。來源本身缺片、過期或所有請求都停住時仍可能轉圈。
- `tests/Js/GksLoaderTest.cjs` 使用固定版 HLS loader 的 stats 結構驗證正常請求、半途停滯、兩份競速、損壞回應、總期限、補發上限、取消與晚到回應；`SportsPlaybackTest.cjs` 驗證固定畫質、原有直播距離、暫停／換源生命週期與保留來源。

## 快取、故障與維護

- Streamed 快取 60 秒；Streameast 快取 120 秒；來源失敗時最多使用 15 分鐘內的最近成功結果並標示過期。
- 失敗後退避 15 秒；單一 HTTP 請求最多 8 秒、連線最多 3 秒。Streamed provider 最多同時 5 個請求。
- 個別來源故障不影響其他来源；首次取得賽程失敗則回傳 503 並顯示重試提示。
- 所有資料使用 Blade 跳脫。播放器起始 URL 只接受設定允許的 HTTPS 主機；不接受任意使用者 URL。賽程／來源資料的後端擷取不跟隨上游重新導向；iframe 內的請求由使用者瀏覽器與原站處理。
- Streameast 仰賴 HTML 結構，鏡像、路徑、播放器主機變更時需重新確認並調整設定／解析器。遇到挑戰頁以故障處理。
- 本機 Docker 的診斷與測試使用 `docker exec --user www-data`，避免 root 建立的快取／鎖檔讓網頁請求立即 503。保持 Laravel cache store 可寫。沿用現有部署流程；若正式環境有 config／route／view cache，部署時正常更新這些快取即可。
